# Почему уходят новички

Запуск запросов: `python3 src/sqlmd.py reports/03_why_newcomers_leave.md`.

## Путь новичка

Как проходил: живой сайт или скриншоты; без аккаунта или с аккаунтом.

Контрольный вопрос: на каком шаге новичку проще всего уйти и что ему в этот момент предлагает сайт?
**Ответ:** Проще всего уйти на шаге 4 — на экране после партии, особенно после поражения. Сайт предлагает «Реванш», «Новый соперник», «Анализ партии» — всё про «сыграть ещё»; анализ в три клика, обучения и задач на этом экране нет.
| Шаг | Что видит новичок | Что может сделать | Где может уйти |
|---|---|---|---|
| 1. Главная | меню, вкладки, кнопки «Создать запрос на игру», «Бросить вызов другу», «Сыграть с компьютером» | не понятно, с чего начать; обучения на главной нет |
| 2. Выбор времени | плитки `1+0`, `3+0`, `10+0`, значки пуля/блиц/рапид | выбирает слишком быструю игру (H2) |
| 3. Первая партия | доска, часы, соперник около 1500 | быстро проигрывает (H4) |
| 4. Экран после партии | итог, ходы, «Реванш», «Новый соперник», «Анализ партии» | **здесь проще всего уйти**: после поражения только «играть дальше» (H1) |
| 5. Анализ партии | окно «нужно зарегистрироваться» (без аккаунта); для зарегистрированного — 3 клика до «Учись на своих ошибках» | требование регистрации, длинная цепочка |
| 6. Регистрация | форма: имя, пароль, почта, две галочки | много полей, не видно зачем |
| 7. Поиск обучения | меню «Обучение»: «Основы шахмат», «Практика» | не находит: на главной и после партии ссылки нет (H3) |
| 8. Задачи | меню «Задачи», Puzzle Streak, Storm, Racer | непонятно, что выбрать |

## Сигналы

Контрольный вопрос: какой сигнал самый громкий, а какой — самый надёжный? Есть ли среди сигналов такой, который опасно брать в работу, и почему?
**Ответ:** Самый громкий — сигнал 5 (уверенный тон, «в полтора раза», «за неделю»). Самый надёжный — сигнал 10: оценка стоимости, её можно сверить с таблицей затрат (среди сигналов о причинах — 6, единственный с подсчётом, но 23 ответа из 1200). Опасно брать в работу сигнал 5: серия дней, которая сгорает, и уведомление «Не потеряй серию!» — давление, нарушает принципы Lichess (флаг `FORBIDDEN_FUNCTION`), число «в полтора раза» нечем проверить.
| Сигнал | К какой гипотезе — или «не про удержание» | Верю или нет — и почему |
|---|---|---|
| 1. Форум: «проиграл семь раз подряд — и всё» | H1 (и H4) | верю частично: один человек, но совпадает с данными |
| 2. Письмо: «обучение нашёл только через поиск» | H3 | верю частично: подтверждает путь новичка |
| 3. Блогер: выбрал `1+0`, проиграл по времени | H2 | не верю как основанию: один пост, проверить нечем |
| 4. Отзыв: «сразу кидают к сильным» | H4 | верю частично: пишет тот, кто остался |
| 5. Идея PM: серия дней и «Не потеряй серию!» | не про причину — готовое решение | не верю и опасно: давление и навязчивость, «в полтора раза» — слух |
| 6. Опрос ушедших: 23 из 1200 | H1/H4, H3 | верю с оговоркой: ответили 1,9%, «нет времени» — вежливая причина |
| 7. Волонтёр: очередь 400 строк | не про удержание: ограничение | верю: короткие строки 1–2 недели, абзацы 3–6 |
| 8. Тёмная тема по умолчанию | не про удержание | не беру: к новичкам не относится |
| 9. Тренер: после проигрыша одна позиция | H1 (и H3) | верю условно: дети с тренером, но данные похожи |
| 10. Разработчик: блок — 3 дня, подбор — недели | не про причину: цена решений | верю: совпадает с таблицей затрат |
| 11. Пост: друзья пришли за компанию и ушли | про состав новичков в волнах | верю: похоже на волны из отчёта 02_cohort_report.md |
| 12. Ветеран: не дёргайте, яркое должно скрываться | условие к решению | верю: блок должен закрываться одним кликом |

```sql
SELECT ROUND(23 * 100.0 / 1200, 1) AS answered_pct,
       ROUND(9 * 100.0 / 23, 1) AS no_time_pct,
       ROUND(6 * 100.0 / 23, 1) AS strong_opponents_pct,
       ROUND(4 * 100.0 / 23, 1) AS cant_learn_pct;
SELECT (puzzles0 > 0 OR lessons0 > 0) AS did_learning, COUNT(*) AS n, ROUND(AVG(back_w1) * 100, 1) AS w1_pct
FROM newcomers
WHERE wins0 = 0 AND full_week = 1 AND (signup_date <= '2026-08-06' OR signup_date >= '2026-09-02')
GROUP BY (puzzles0 > 0 OR lessons0 > 0);
```

## Гипотезы

Контрольный вопрос: какой результат запроса опроверг бы гипотезу? Для гипотезы с самым сильным вердиктом — какое другое объяснение даёт тот же результат?
**Ответ:** H1 опровергла бы разница возврата меньше 5 п.п. или её исчезновение внутри периода; на деле 26–34 п.п. H3 опровергла бы одинаковый возврат у занимавшихся и остальных; на деле +7–13 п.п. H2 и H4 этими данными не проверить. Самый сильный вердикт — у H1. Другое объяснение того же результата: и поражение, и уход вызваны слабым интересом новичка; проигрыш — маркер ухода, а не его причина. Различит только эксперимент.
### H1. После поражения — тупик

Шаг пути: 4 — экран после партии.

Если гипотеза верна, в данных будет видно: проигравшие все партии в день регистрации (`wins0 = 0`) возвращаются реже, чем выигравшие хотя бы раз, и при том же числе партий.

Вердикт: не опровергнута, но есть другое объяснение.

**Ответ:** `wins0 = 0` — 7781 новичок из 19 977 с полной неделей: `back_d1` 16,4% против 39,0%, `back_w1` 25,7% против 60,2% (разница 34,5 п.п.). При `games0` = 1: 24,6% против 53,8%; при 2: 25,9% против 57,4%; при 3: 27,2% против 60,9%. Другое объяснение: проигрыш — признак слабого интереса.

```sql
SELECT wins0 = 0 AS lost_all, COUNT(*) AS n,
       ROUND(AVG(back_d1) * 100, 1) AS d1_pct,
       ROUND(AVG(back_w1) * 100, 1) AS w1_pct
FROM newcomers
WHERE full_week = 1
GROUP BY wins0 = 0;
SELECT games0, wins0 = 0 AS lost_all, COUNT(*) AS n, ROUND(AVG(back_w1) * 100, 1) AS w1_pct
FROM newcomers
WHERE full_week = 1 AND games0 IN (1, 2, 3)
GROUP BY games0, wins0 = 0
ORDER BY games0, lost_all;
```

### H2. Быстрая игра слишком быстрая

Шаг пути: 2 — выбор контроля времени.

Если гипотеза верна, в данных будет видно: у выбравших `1+0` и `2+1` много поражений по времени и они реже возвращаются.

Вердикт: не проверить этими данными. Не хватает по каждой партии: контроль времени, чем кончилась (мат, сдача, время), число ходов. Собрать можно без новых счётчиков — Lichess хранит эти поля в записи партии, достаточно обезличенной выгрузки.

**Ответ:** в `activity` и `newcomers` только число партий, побед, задач и уроков — контроля времени нет.

```sql
SELECT name, sql FROM sqlite_master WHERE name IN ('activity', 'newcomers');
```

### H3. Обучение спрятано

Шаг пути: 7 — поиск обучения.

Если гипотеза верна, в данных будет видно: обучением в день регистрации занимается меньшинство, а занимавшиеся возвращаются чаще.

Вердикт: не опровергнута, но есть другое объяснение.

**Ответ:** Задачи или уроки в день регистрации делали 39,0% новичков июля, 23,0% августа, 37,4% сентября. До 6 августа возврат за неделю: занимавшиеся 68,6% (1889 человек), остальные 61,2% (2899). Другое объяснение: учатся самые заинтересованные; что вход «спрятан», данными не проверить

```sql
SELECT signup_month, COUNT(*) AS n, ROUND(AVG(puzzles0 > 0 OR lessons0 > 0) * 100, 1) AS learned_pct
FROM newcomers
GROUP BY signup_month;
SELECT (puzzles0 > 0 OR lessons0 > 0) AS learned, COUNT(*) AS n,
       ROUND(AVG(back_d1) * 100, 1) AS d1_pct,
       ROUND(AVG(back_w1) * 100, 1) AS w1_pct
FROM newcomers
WHERE full_week = 1 AND signup_date <= '2026-08-06'
GROUP BY (puzzles0 > 0 OR lessons0 > 0);
```

### H4. Первый рейтинг врёт

Шаг пути: 3 — первая партия.

Если гипотеза верна, в данных будет видно: в день регистрации новички выигрывают реже, чем потом, и реже старых пользователей.

Вердикт: не проверить этими данными. Не хватает рейтинга игрока и соперника перед каждой партией.

**Ответ:** Доля побед: новички в день регистрации 38,0%, дни 1–7 — 41,8%, позже — 42,8%, старые — 50,0%. Согласуется с H4, но так же объясняется тем, что новички просто слабее.

```sql
SELECT CASE WHEN signup_date < '2026-07-01' THEN '1 старые'
            WHEN day_n = 0 THEN '2 новички, день регистрации'
            WHEN day_n BETWEEN 1 AND 7 THEN '3 новички, дни 1-7'
            ELSE '4 новички, день 8 и позже' END AS grp,
       COUNT(*) AS user_days,
       ROUND(SUM(wins) * 100.0 / SUM(games), 1) AS win_rate_pct
FROM act
GROUP BY grp
ORDER BY grp;
```

### Проверка на честность

Гипотеза, которая выглядит сильнее всех, — проверка внутри одного периода из отчёта 02_cohort_report.md.

Контрольный вопрос: эффект остался, изменился или пропал? Почему это важно?

**Ответ:** Самая сильная — H1. Внутри каждого периода из отчёта 02_cohort_report.md возврат за неделю у проигравших против остальных: A 39,4% против 70,9%; B 21,1% против 47,3%; C 28,8% против 62,1%; D 22,5% против 50,2%; E 34,9% против 68,7% — разница 26–34 п.п. остаётся во всех периодах. Но доля проигравших в волнах вдвое выше (B 52,2%, D 50,8% против A 21,6%, E 26,9%), поэтому общую разницу 34,5 п.п. нельзя брать как есть — часть её от смешения периодов. Эффект остался внутри периода, значит H1 — не артефакт волн; причину (поражение или слабый интерес) это не доказывает.

```sql
SELECT CASE WHEN signup_date <= '2026-08-06' THEN 'A 01.07-06.08'
            WHEN signup_date <= '2026-08-16' THEN 'B 07.08-16.08'
            WHEN signup_date <= '2026-08-27' THEN 'C 17.08-27.08'
            WHEN signup_date <= '2026-09-01' THEN 'D 28.08-01.09'
            ELSE 'E 02.09-28.09' END AS period,
       wins0 = 0 AS lost_all,
       COUNT(*) AS n,
       ROUND(AVG(back_w1) * 100, 1) AS w1_pct
FROM newcomers
WHERE full_week = 1
GROUP BY period, lost_all
ORDER BY period, lost_all;
SELECT CASE WHEN signup_date <= '2026-08-06' THEN 'A 01.07-06.08'
            WHEN signup_date <= '2026-08-16' THEN 'B 07.08-16.08'
            WHEN signup_date <= '2026-08-27' THEN 'C 17.08-27.08'
            WHEN signup_date <= '2026-09-01' THEN 'D 28.08-01.09'
            ELSE 'E 02.09-28.09' END AS period,
       COUNT(*) AS n,
       ROUND(AVG(wins0 = 0) * 100, 1) AS lost_all_pct
FROM newcomers
WHERE full_week = 1
GROUP BY period
ORDER BY period;
```
